Eight systems, all of them running

Most of my code is private because most of it runs businesses. Here is what each system does, what it is built on, and what I can show you live.

01 / OPERATIONS PLATFORM 2024 → now production

Mobigo

Contract signing and WhatsApp operations for my phone rental business. A self-hosted DocuSeal instance issues the rental agreements, the same stack sends the signing links, and a WhatsApp session manager keeps every customer conversation attached to the right agreement.

  • Self-hosted e-signature with custom agreement templates, including CTOS and CBM consent forms
  • Multiple WhatsApp sessions, each with its own forwarding rules and staff routing
  • IMEI level device records, so a returned phone is provably the one that went out
  • Submission inbox that links a signed PDF back to the customer record automatically

TypeScript, Node, Docker, Postgres, Redis, MongoDB, DocuSeal

02 / BROWSER EXTENSION 2025 → now live on the store

Learn Language with DualSub

A Chrome extension that puts two subtitle tracks on the same video and teaches one word at a time. Three modes: a native secondary track, YouTube's own caption translation, or live AI translation. In AI mode a single structured call translates the line and picks the words worth learning together.

  • Word picks are graded across a shared CEFR, HSK, JLPT and TOPIK scale, then highlighted in both languages
  • Every highlight is saved automatically under its dictionary form, so plurals and conjugations collapse into one word
  • Marketing site in seven languages, Google sign-in, and a study portal with cloud word sync and quizzes
  • Evaluation harness: 530 real subtitle lines across 14 language pairs, graded blind by a second model, before a prompt is allowed to become the default

Chrome MV3, Astro, Express, MongoDB, OpenRouter

03 / VOICE 2026 production

Mulatie voice agent

A real-time speech-to-speech agent built on Pipecat and deployed to its own box. Audio streams both directions, the agent tolerates being interrupted mid sentence, and the product is wrapped in a Chinese-first interface for its users.

  • Streaming voice pipeline with turn detection and barge-in
  • Single-purpose server with its own deploy path and health checks
  • Key-gated access and per-user session handling

Python, Pipecat, WebRTC, Docker, AWS

04 / MESSAGING AUTOMATION 2026 production

WhatsBlast

WhatsApp campaign tool built for multiple paired numbers at once. It queues campaigns, paces sends so a number does not get flagged, and keeps session credentials in Redis so a restart does not cost a re-pair.

  • Multi-session management with per-number throughput control
  • Queue with retries and failure accounting per recipient
  • Redis-only session state, which makes redeploys painless

Node, Redis, whatsapp-web.js, Docker

05 / HARDWARE + WEB 2026 production

Bridgly SMS gateway

A control centre for a fleet of Android handsets that send SMS through their own SIM cards, plus the Android app that runs on each phone. Devices report battery, signal and last heartbeat, and the console routes each campaign to the right device and SIM.

  • Live device registry with heartbeat and battery telemetry
  • Single sends and CSV bulk uploads with per-message status
  • Per-SIM routing and transmission logs for every message

TypeScript, websockets, Android APK, Docker

06 / LOCAL AI TOOLING 2026 personal build

Zimu subtitle translator

A desktop tool for translating and burning bilingual subtitles into video files, running entirely on a local RTX 4060. No cloud upload, no per-minute billing, which matters when the source material is long.

  • Local transcription and translation pipeline
  • Bilingual subtitle burn-in with styling control
  • Chunked processing so long videos survive a laptop sleep

Python, ffmpeg, local GPU inference

07 / OPEN SOURCE 2026 public repo

WhatsApp agent gateway

A two-part open-source kit: a WhatsApp gateway that owns the session, and a receiver that lets an AI agent hold a real conversation through it. Session recovery, message history, tool calls, and a clean seam between the messaging layer and the agent.

  • Baileys-based gateway with reconnection and re-pair handling
  • Receiver process that turns messages into agent turns and sends replies back
  • History store so conversations survive restarts

TypeScript, Baileys, Node
